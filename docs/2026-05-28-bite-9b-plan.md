## What this bite delivers

Removes the parallel MP config parse from tdns/v2. After bite 9b
lands, `tdns.Config.MultiProvider`, `tdns.MultiProviderConf`, and
all related types/functions are gone. Standalone `tdns-agent` and
`tdns-auth` lose MP capability entirely — MP daemons must run as
`tdns-mpagent` / `tdns-mpsigner` (etc.) under tdns-mp.

## Parity verification (9b-pre)

Bite 9a copied code from tdns to tdns-mp. Before deleting from tdns,
confirm tdns-mp has functional parity.

### `parseMultiProviderOptions` (B9b-9)

Compared:
- tdns/v2/parseoptions.go:141-192
- tdns-mp/v2/mp_config_parse.go:130-169 (parseMultiProviderOptions, top-level not method)

**Parity:** full. All three option blocks (Combiner, Signer, Agent)
have the same lookup logic, the same legacy `AddSignature` migration.

**Gap:** tdns logs `lg.Warn("unknown combiner option, ignoring", ...)`
(and Signer / Agent equivalents) when a string doesn't match a known
option. tdns-mp's version skips silently.

**Decision:** add the warn-on-unknown logs to tdns-mp's
`parseMultiProviderOptions` before B9b-9 lands. Quiet failure on a
misconfigured option-name is a regression we'd notice only when
someone wonders why their `combiner-options: [foo]` had no effect.

### `normalizeConfigIdentities` MP branches (B9b-7)

Compared:
- tdns/v2/parseconfig.go:1419-1445 (MP branches inside the larger
  `normalizeConfigIdentities()`)
- tdns-mp/v2/mp_config_parse.go:89-128 `normalizeMultiProviderIdentities`

**Parity:** full field coverage:

| Field | tdns | tdns-mp |
|---|---|---|
| `Identity` | guarded `!= ""` | guarded `!= ""` |
| `Dns.ControlZone` | guarded | guarded |
| `Combiner.Identity` | guarded | guarded |
| `Signer.Identity` | guarded | guarded |
| `AuthorizedPeers[]` | unconditional | **stricter**: skips empty/whitespace (commit 0d65163) |
| `Peers[].Identity` | guarded | guarded |
| `Agents[].Identity` | guarded | guarded |
| `ProtectedNamespaces[]` (combiner-only) | unconditional | **stricter**: skips empty/whitespace (commit 0d65163) |

tdns-mp is stricter than tdns on two fields (CodeRabbit finding
addressed). Nothing in tdns that's missing in tdns-mp.

**Decision:** no migration needed. Drop tdns side as part of struct
deletion.

### B9b-2 / `ConfigResponse` analogue in tdns-mp

Grep result: tdns-mp has no `ConfigResponse` analogue, and no
`combiner config status` CLI subcommand exists. The only related
subcommand is `tdns-mpcli agent config` (agent-side details).

**Decision:** B9b-15 creates `tdns-mpcli combiner config status -v`
+ its `*Config` method + a tdns-mp `ConfigResponse` struct.

## Execution order

Each step is its own commit. Step 4 lands in tdns, all others in
tdns-mp.

### 9b-step-1 (tdns-mp)
- Migrate `LocalIdentity()` callers in tdns-mp to
  `conf.MpConfig().Identity` (B9b-4 caller side, 4+ sites).
- Restructure the `OptMultiProvider` zone validator in
  `tdns-mp/v2/main_init.go:51` to read from `WiredMpConfig()`
  (B9b-11).
- Verify all 5 mp* binaries build.

### 9b-step-2 (tdns-mp): B9b-15
- Add `tdns-mpcli combiner config status -v` subcommand.
- Add the corresponding `*Config` method on the combiner side.
- Add a tdns-mp `ConfigResponse` struct (or similar; bikeshed on
  name during implementation). Includes CombinerOptions and
  whatever else makes sense for combiner-side runtime introspection.
- Verify the subcommand returns sensible output against a running
  mpcombiner (note: testing happens on operator's VMs, but the
  build + struct shape can be sanity-checked here).

### 9b-step-3 (tdns-mp): B9b-12 + B9b-13
- B9b-12: move validators in `config_validate.go` from
  `*tdns.Config` to `*tdnsmp.MultiProviderConf`. Wire them into
  the parser hook (right after `parseMultiProvider` returns) so
  validation runs against the local parse with errors propagating
  through the hook return. Stop using `tdns.PostValidateConfigHook`
  for MP validation.
- B9b-13: rewrite `LoadConfigForKeys` to use a focused YAML
  decoder targeting just the `multi-provider:` subtree into
  `*tdnsmp.MultiProviderConf`. `getKeysPrivKeyPath` takes the
  decoded type directly.
- Also add the warn-on-unknown logs to
  `parseMultiProviderOptions` (the parity gap noted above).

### 9b-step-4 (tdns)
Only after tdns-mp is fully self-contained. In a single tdns commit:
- Delete `MultiProviderConf` struct + sub-types (B9b-final).
- Delete `MultiProvider` field on `tdns.Config`.
- Delete `LocalIdentity()` (B9b-4).
- Delete `AgentMgmtResponse.AgentConfig` (B9b-1).
- Delete `ConfigResponse.CombinerOptions` field (B9b-2).
- Delete the populate site in `apihandler_funcs.go` (B9b-3).
- Delete `parseMultiProviderOptions` + the call site in
  `parseconfig.go` (B9b-8 + B9b-9).
- Delete MP branches in `normalizeConfigIdentities` (B9b-7).
- Delete role-match validation (B9b-5).
- Simplify the primary-zone-on-agent error path (B9b-6).
- Delete MP code paths in `tdns/cmdv2/agent/main.go` etc. (B9b-14).
- Delete the `CombinerOptions` rendering in tdns-cli (B9b-10).
- Delete the option type enums (`CombinerOption` etc.) + their maps.

### 9b-step-5 (tdns-mp)
- Bump tdns version pin in tdns-mp/v2/go.mod (and cmd/*/go.mod via
  `make bump-johanix-deps`).
- Drop `wiredMpConfig = conf.MultiProvider` bridge line in
  MainInit (now a type error since `tdns.Config.MultiProvider` is
  gone). It was already redundant after 9a (the parser hook sets
  `wiredMpConfig` directly) — this just removes the now-broken
  line.
- Drop the comment in tdns-mp's `multi_provider_conf.go` referring
  to "the tdns side populates conf.Config.MultiProvider" (no
  longer accurate).
- Verify all 5 mp* binaries build against the new tdns version.

After step 5 lands, `peer-discovery-engine-extraction` and
`feat/sig-validity-mp-sync` need their next merge from

## PR strategy

Default: one PR per repo.

- **tdns-mp PR**: all of step-1, step-2, step-3, step-5. (Or split
  step-2 off as its own PR if B9b-15 ends up being substantial
  user-facing functionality. Decide during step-2.)

  PR is on origin/main and the tdns-mp side is fully self-contained.

PR #31 (the current bite 1-9a PR) stays open and unmerged through
all of this; it merges only after step-5 lands.
